# AltRosetta development

- Investigate and state evidence before claiming execution compatibility.
- Keep the repository private until the user explicitly requests publication.
- Never commit commercial applications, installers, activation records, keys or user documents.
- Do not modify or re-sign `/Applications/HwpMac2014.app`.
- Do not disable SIP/AMFI, modify kernels, or bypass product activation.
- Keep fetched upstream code under `.local/upstreams/`; pin inspected SHAs in research notes.
- Original code is MIT; preserve upstream notices if code is integrated.
- Run `python3 -m unittest discover -s tests -v` for inspector changes.
- For native probes, build with CMake and run `ctest --output-on-failure` on ARM64 macOS.
- Never execute a fixture directly on macOS and label it Rosetta-independent.
- `os_cross_arch_is_supported` reports kernel support only, not entitlement authorization.

## Installer and runtime security gates

- Read [ADR-002](docs/adr/002-malware-safety.md) **before** writing installer, scanner, translator or runtime code.
- Default to read-only package inspection. Never run `installer`, `preinstall/postinstall`, unsigned helpers, Windows setup EXE or other untrusted code in a research/inspection command.
- Scan verdicts **fail closed**: missing/invalid/outdated signature DB, crashed or timed-out worker, archive limits or incomplete coverage are not clean outcomes.
- v1 **must not** ship privileged/root installation helpers, kernel/system/DriverKit extensions, Windows kernel-driver installation, external Linux kernel modules, or SIP/AMFI/Gatekeeper bypass.
- Treat a Wine prefix, a separate process, and a file path under Application Support as **not by themselves sandboxed**. Explicitly prove OS-level isolation before enabling untrusted execution.
- Run malware/file-parsing engines in least-privilege isolated processes; preserve macOS Gatekeeper and XProtect.
- Maintain test fixtures generated by the project, including clean, malformed, limits-exceeded, and EICAR; never check actual malware into the repository.
- Report scanner engine/database version, coverage, changed-file hash and policy verdict; never describe a signature-negative file as proven safe.
- Keep release/packaging license notices and source obligations for any ClamAV (GPL-2.0) executable distinct from original MIT project source; YARA-X is BSD-3-Clause.
